# Improvement Proposals

Each candidate is one Markdown file named `YYYYMMDD-NNN-short-title.md` with frontmatter ID `LRN-YYYYMMDD-NNN`.

Use `TEMPLATE.md` for every proposal. Keep one root cause and one coherent outcome per proposal. Split unrelated ideas even when they could be implemented together.

## Status

- `proposed` — evidence collected; no owner decision yet.
- `approved` — owner explicitly approved implementation.
- `implementing` — an approved change is being developed.
- `awaiting-review` — implementation and validation are ready for independent review.
- `changes-requested` — review or owner found a bounded correction.
- `adopted` — owner accepted the verified outcome.
- `rejected` — owner declined the proposal or later evidence invalidated it.

Only the owner-facing approval agent may write approval, rejection, or adoption decisions. The observer may only create `proposed` files. The implementer may only advance an approved proposal through `awaiting-review`.
